# Commands and their scientific scope

Use `python companion.py --help` and the help of each subcommand. All result directories must be new and outside the companion. A successful command writes a result record; a failed numerical command writes a failure record with partial-output status. Never treat a partial file as an accepted result. Commands listed here are supported routes, **not a claim that every route passed**. The [dated validation report](VALIDATION.md) identifies the exact tested scopes, failed installation and guard/permission rejections. The current executable and scientific payload is unchanged from the validated archive. Later numerical executions must recheck the actual environment and applicable permissions.

## Standard-library and saved-file operations

```sh
python companion.py verify
python companion.py studies
python companion.py outputs
python companion.py export-output --id article.table.2 --out ../table2-evidence
```

`verify` checks the complete export inventory and hashes, excluding only Git administrative data and Python caches. It rejects symlinks, altered/missing files and unexpected payload. The manifest is not a digital signature: compare the ZIP against its independent delivery receipt before trusting its contents. `outputs` lists every current article/guide output. `export-output` copies listed saved files; it does not recompute values.

With a separately installed TeX distribution:

```sh
python companion.py figures --out ../six-numerical-figures
python companion.py figures --only continuing_diagnostics --out ../continuing-figure
python companion.py guide --out ../computational-guide-build
```

These compile retained coordinates/document sources, with shell escape disabled. They do not execute the numerical experiments. The six numerical figures exclude the article's conceptual architecture diagram. `guide` is computational documentation, not the proof supplement.

## Fixed-record aggregation and saved-policy evaluation

```sh
python companion.py aggregate --study reported --out ../reported-aggregation
python companion.py aggregate --study four_state_continuing --out ../continuing-aggregation
python companion.py evaluate --study four_state_reset --scope all --out ../four-state-policy-check
python companion.py evaluate --study four_state_continuing --scope all --out ../continuing-policy-check
python companion.py evaluate --study lactose_first_arrival --scope endpoint --out ../first-arrival-policy-check
```

Aggregation uses saved observations/indices, not new independent seeds. The continuing aggregate command regenerates its 247 curve groups; the other nine retained scalar tables are not regenerated by that command. The broader evidence collection, count-only training-budget files and displayed table rows are preserved records; the presence of a route does not imply every reported scalar is recomputed by a single command.

Saved-policy evaluation solves or simulates the specified policy; unlike saved-file export, this is numerical execution. The continuing path evaluates 130 saved states in two modes with frozen training/RNG state. Endpoint-only mode is narrower. Biological evaluation additionally requires exact external inputs and permission acknowledgement:

```sh
python companion.py evaluate --study melanoma_xor --scope endpoint --input-dir ../permitted-inputs --acknowledge-local-use-rights --out ../melanoma-xor-evaluation
python companion.py evaluate --study melanoma_persistent --scope endpoint --input-dir ../permitted-inputs --acknowledge-local-use-rights --out ../melanoma-force-evaluation
```

## Reference and diagnostic operations

```sh
python companion.py witness --out ../witness-certificates
python companion.py references --study four_state_reset --out ../four-state-references
python companion.py references --study lactose_first_arrival --out ../first-arrival-certificates
python companion.py diagnostics --out ../initialization-diagnostic
python companion.py meanfield --iterations 620 --out ../meanfield-diagnostic
```

`witness` checks the retained interval witness and two saved-support certificates; it does not search for a new optimum. Four-state references perform the declared exact-model computations. The first-arrival command checks saved reference/certificate material rather than providing a freshly validated constrained optimizer. `diagnostics` is a fixed synthetic initialization check with no training steps. The deterministic mean-field calculation is separate from sampled continuing learning and first-arrival stopping.

## Training and bounded software checks

```sh
python companion.py continuing-check --seed 900 --decisions 128 --out ../software-check
python companion.py continuing-check --seed 900 --decisions 64 --out ../software-prefix
python companion.py continuing-check --seed 900 --decisions 128 --resume ../software-prefix/checkpoint --out ../software-resume
```

The continuing check accepts only reserved software-check seeds 900–909 and at most 2048 decisions. These are not new scientific replicates. The production activation guard remains closed.

The general `train` command exposes the retained declared routines for `four_state_reset`, `lactose_first_arrival`, `melanoma_xor` and `melanoma_persistent`. `--profile smoke` is a functional path, not the scientific budget. `--method`, `--seed`, `--budget` and exact configurations determine scope. Biological training requires the same external input and acknowledgement arguments as evaluation. Having a command is not authorization to alter the study, add seeds or select favorable reruns. Consult the configurations and scientific protocol before executing it.

## Biological continuation and external restart inspection

```sh
python companion.py eligibility --out ../environment-check
python companion.py restart-inputs --state-dir ../permitted-restart --acknowledge-local-use-rights --out ../restart-identities
python companion.py restart-inspect --state-dir ../permitted-restart --acknowledge-local-use-rights --out ../restart-inspection
```

The first command checks the actual host against the exact recorded historical descriptor. A mismatch is a rejection, not a numerical pass. The next two inspect external bytes/schemas; inspection is not live model or optimizer restoration.

`continuation-replay` requires `--state-dir`, `--input-dir`, `--run-id`, `--stop` (480, 720, 960 or 1200), permission acknowledgement and a new output directory. Only the preselected seed-zero run identifiers in the external manifest are accepted. The exact environment is checked before external biological state/model loading; authorization and input identities are then checked. No override or automatic new-run authorization is supplied.

## Tests

`python -I -S tests/test_export_structure.py` runs only structural/transport/guard-order fixtures with the standard library. `python test.py` discovers the numerical contract tests, which require the stated numerical dependencies. Their outcomes must be recorded separately. Neither command is a clean installation test. See `TESTING.md`.
